一镜到底的连贯动效。

做产品发布片、预告片、功能演示。每一个画面都从上一个画面里长出来，是一整条连续的镜头，而不是一张张轮流出场的 PPT。

来自 onetake 自己的发布片。一条提示栏（prompt bar）展开成它请求生成的广告；下一条提示塌缩成一条线，扫过桌面后展开为一块银幕。无剪辑。

散架的动效

如今 AI 生成的大多数动效视频，还有大多数模板工具，做出来都是松散的。标题卡，渐隐，UI（用户界面）镜头，渐隐，功能卡，渐隐，Logo。单个镜头看着都没毛病，但合在一起读起来还是幻灯片，因为这一拍和下一拍之间没有任何东西在传递，场景只是彼此替换。

每个节拍都承过去

onetake 把两个节拍之间的边界当成真正要设计的东西。在每一个边界处，屏幕上都会有一块东西活下来，可见地变成下一个节拍。提示栏展开成应用窗口，窗口重新排布成手机，一根横条塌缩成一条线，那条线扫过桌面后变成下一支片子的第一条网格线。一张卡片长成一页，舞台从角色身上打开，摄影机穿过一张卡片，直到那张卡片本身就成了下一个场景。结尾处，所有角色折入品牌锁定组合（lockup）；在发布片里，方块光标一笔写下名字。

一台摄影机把整条片子串起来

它从不剪辑。永远比主体提前一拍跟随，甩向下一个元素将要落点的位置，像手持摄影师一样漂浮。被撞击时会摇晃，然后纹丝不动地稳持，因为停顿才是让动作落地的关键。

连续性是测出来的，不是盼出来的

每一支片子在被人看之前，都会被一个 oracle（自动判定程序）先过一遍。

probe.py 记录每一帧在显示什么，找出每个边界，然后追问有什么东西跨过去了。节拍之间只是替换、毫无承接的片子，会被直接判失败。

| 影片 | 判定 | 连续性（承转分数） |
| --- | --- | --- |
| 早期发布片 v1，节奏完美，仍是幻灯片 | 拒绝 | 0.00 |
| 同一支片 v2 | 拒绝 | 0.40 |
| 同一支片 v3，每一拍都从前一拍长出 | 通过 | 0.75 |
| onetake 发布片 | 通过 | 0.83 |同一套 oracle 也会判失败。节奏均匀，所有镜头时长一样。没有停顿。音频被截断。高速动作缺运动模糊。主体跑出画面。这些情况全都过不了。

真实 UI，原样重建

产品的界面从截图里用 HTML（超文本标记语言）重建出来，落在摄影机所在的平面上。所以摄影机可以任意缩放地飞进去。不是屏幕录像。

被测量的动作

约 38 个动作（springs 弹性、entrances 入场、carries 承转、contact 接触、sims 模拟、camera 摄影机、fluid grounds 流体地面），每一个都是时间的纯函数，速度曲线是被测出来的，绝不是手搓的缓动。

编辑导读

onetake 是一个 Claude Agent Skill，专注生成不切镜头的连续动画影片：每一帧画面从前一帧过渡而来，整段保持同一虚拟机位，画面衔接由连续性判定 oracle 评估。它适合产品发布片和功能演示场景，能产出连贯的运动图形。★305，Python 实现。

为什么读它把连贯性作为一等约束交给 oracle 打分，而不是依赖抽卡式的随机生成。
