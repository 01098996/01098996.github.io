100 步 GRPO 微调 350M 模型以获得更优的结构化输出

结构化输出是 LLM 最常见的现实任务之一，但大多数基准测试都把它并入更广泛的推理或抽取评分中，而没有单独衡量它。一个模型是否能够在请求的格式与形态下可靠地返回有效、可解析的输出——即模式合规性（schema compliance）——往往决定了它能否被接入下游系统。

请注意，本文所述的训练流程并非用于训练

IFStruct 博客

中所述 RL 模型的那一套。本 notebook 的目标并非复现 IFStruct 基准分数，而是展示针对特定任务对较小模型进行微调可以提升其表现，并使其与远大于它的模型相媲美。

训练数据

我们使用

nvidia/Nemotron-RL-instruction_following-structured_outputs

，它将每个提示与一个目标 JSON Schema 以及期望的字段数配对。我们使用约 500 个样本进行训练。

由于 Nemotron 数据分布与 IFStruct 评估不同，我们对提示做了增强以弥合两者之间的两个差距：

40%

的样本在末尾追加一条"将输出放入围栏代码块内"的指令，使模型学会

遵循格式指令

，而非始终直接输出原始 JSON。

与之不相交的另外

20%

被转换为顶层数组任务（模式被包裹在一个

array

中，并指定必需的条目数），以此训练裸列表输出与条目数合规性。

模型与 LoRA

我们加载

LiquidAI/LFM2.5-350M

并为其附加一个 LoRA 适配器。由于 LFM2.5 使用混合注意力/卷积架构，我们针对 LFM 特定的模块名进行指定：

lora_config = LoraConfig(
    r=,
    lora_alpha=,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=[
        "q_proj",
        "k_proj",
        "v_proj",
        "out_proj",
        "in_proj",
        "w1",
        "w2",
        "w3",
    ],
)

这会训练约 6M 个参数，约为模型总参数的 1.66%。

奖励函数

接着我们定义三个奖励函数，每个都在

[0, 1]

区间上取值，对每个补全根据其抽取出的

结构

是否正确进行打分：

- json_format_reward：输出是否可解析，并且是否为请求的形式？请求形式（围栏代码块 vs. 原始）得满分（

1.0

），可解析但形式错误得

0.2

，无法解析得

0.0

。
- field_count_reward：对象是否具有期望数量的顶层字段？精确匹配得

1.0

，分数随偏差线性衰减。
- schema_validation_reward：输出是否针对该行的 JSON Schema 通过校验？它统计每一条约束违反，并在必要键覆盖基础上给予部分奖励。

我们将三者以加权和方式组合，权重为 reward_weights=[1.0, 0.5, 2.0]。

结论

仅用约 500 个样本、100 步的简短 GRPO 训练，就能将一个 3.5 亿参数的小模型在 IFStruct 上的表现从 22.6% 提升到 29.7%。其要点在于：一种廉价、任务特定的奖励信号，能够显著提升小模型在结构化输出可靠性上的表现。
