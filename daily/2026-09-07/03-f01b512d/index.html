让你的编程智能体拥有一份由你掌控的记忆

我在多台机器上工作，并会根据任务切换不同的编程智能体（coding agent）。

每一个智能体都像陌生人一样面对我的项目。上周二那轮推理一旦会话结束，就会随之消失。每换一个智能体、每换一台主机，它都会从零开始。

今年早些时候，《Software Forgets: Agent Traces Are the Memory》指出，编程智能体其实已经产生了我们不断丢失的记录。当它们搜索代码库、尝试不同方案、遇到错误、阅读文档并调整方向时，会留下关于“改变了什么”以及“为什么改变”的详尽记录。

这个判断虽然正确，但轨迹（trace）也只是潜在的记忆。智能体的会话日志仍然只是一份档案。你无法通过 grep 从一万轮记录中找出“我们为什么弃用流式解析器？”。要让智能体在工作过程中实际使用这些轨迹，就需要索引（indexing）、检索（retrieval）、排序（ranking）和精确溯源（exact provenance）。

这正是 funes 所提供的。它是面向智能体（Claude Code、Codex、pi 和 Hermes）的持久记忆层（durable memory layer），由你机器上已有的会话（session）构建。它在本地运行，只需一条命令，就能融入智能体的正常工作流程。你也可以选择让它迁移到你拥有的 Hugging Face 数据集（dataset）中，默认保持私有。

为你正在使用的智能体添加记忆

funes 是一个独立的二进制程序。其默认推理后端（default inference backend）不依赖任何机器学习运行时（ML runtime），嵌入（embedding）与重排（reranking）都在你的机器上完成。安装它：

curl -fsSL https://huggingface.co/buckets/huggingface/funes/resolve/install.sh | sh

然后将它添加到智能体：

funes add claude

# or: codex, pi, hermes

这条 add 命令会构建第一份索引，为智能体提供 recall 和 get 工具，并安装用于索引每个已完成轮次的自动化机制。索引采用增量方式（incrementally）：新的运行只会加入新的轮次，而不会再次嵌入全部历史。更早、更深层的内容则可以按批次逐步回填，且每批都有上限。

接下来，你只需照常工作。当某项任务涉及过去的决策、理由或发现时，智能体可以自行调用 recall。你无需记住旧会话，也不必把旧上下文粘贴到新会话中。

添加 funes 后，召回会在对话内部进行。智能体会主动访问自己的记忆，并指出答案来自哪个会话。

recall 返回的是原始文本，而不是摘要，并会准确标明其来源，包括智能体、时间戳、会话和轮次（turn）。每个结果都包含一个 get 命令，可打开完整轮次及其周边上下文。

在底层，一条确定性的流水线（pipeline）会将每种受支持的轨迹解析为统一的“轮次—内容块”（turn-and-block）结构，对其进行分块，使用固定版本的本地模型（pinned local model）生成嵌入，然后写入本地的 Lance 数据集。一次查询会结合向量搜索（vector search）与 BM25 搜索，融合两者的排名结果，使用交叉编码器（cross-encoder）重排候选结果，再根据时效性重新加权，并附上相邻分块。

这种设计赋予 funes 三项重要特性：

跨智能体共享同一份记忆

Claude Code、Codex、pi 和 Hermes 都会写入同一种数据结构。recall 可以跨越它们的全部历史记录，而每次命中都会标明由哪个智能体产生。

原始证据始终完整

内容在写入时不会被提炼成事实。每个结果始终可以追溯到产生它的轮次。

recall 默认在本地运行

无需账户或 Hub 仓库。托管模型不会处理你的会话来建立索引；嵌入和重排在你的机器上运行，推理则由你的编程智能体完成。

在单台机器上，“智能体如同陌生人”的问题已经得到解决。但当下一台机器上的新智能体开始工作时，记忆会变得更加有用。

记忆是数据集，而不是服务

要让你工作中的记忆随之迁移，可以在将 funes 添加到智能体时绑定一份记忆：

funes add codex acme/funes-memory

绑定操作会将你当前的记忆发布到那里。之后，funes 会持续保持其更新：在本地索引每个轮次，并在会话边界处发布。智能体在整个过程中都可以从中召回信息。在另一台机器上运行同一条命令，这份记忆也会随你迁移过去。

底层，本地记忆是一份 Lance 数据集；共享记忆则是一份由你拥有的 Hugging Face 数据集，默认保持私有。

任何内容在进入 Hub 之前，凭据（credentials）就已经在索引过程中完成脱敏。发布时还会再次扫描每个分块，并拦截任何看起来仍然像秘密的内容。负责此事的扫描器记录在 SECURITY.md 中，其中说明了它会处理什么，以及不涵盖什么。

当智能体读取远程记忆时，funes 会在本地缓存数据集文件，因此热查询（warm query）能够恢复本地速度。Hub 则提供它已经为其他数据集提供的所有权、访问控制、版本管理和分发能力。你的记忆不会变成另一个记忆服务中的账户，你也不必再通过 API 将它租回来。

先询问，再接入

recall 是专为智能体设计的。如果你想亲自向记忆提问，可以使用 ask。它默认读取本地记忆：

funes ask claude "what did we decide about the streaming parser"

也可以让它指向一份共享记忆。我们发布了一份关于 funes 开发的记忆，因此你无需创建自己的记忆，也能询问 funes 为什么会采用当前的工作方式：

funes ask claude "why is funes append-only" --memory huggingface/funes-memory

funes ask 是 funes add 的只读、每次只回答一个问题的兄弟命令。它会召回相关段落，将其交给编程智能体，并返回一个有充分依据（grounded）、且会标明来源的答案。它不会安装集成，也不会更改智能体的持久配置。

检索未命中（retrieval miss）不会被草率掩盖。如果相关段落不足以支持答案，智能体会明确说明。你可以重新表述问题，或者将 funes 添加到智能体中，让它能在正常工作过程中反复搜索记忆。

切换智能体，不丢失思路脉络

共享记忆并不依附于创建它的智能体或模型。你可以本周在 Claude Code 中开始一项任务，下周再从 Codex 继续，第二个智能体仍然能够召回第一个智能体的推理过程。你可以使用搭配本地模型的 pi，或使用通过 Hugging Face 路由器（router）提供的模型，然后返回 Claude。

Claude 作出决策，钩子（hook）对决策建立索引，Codex 则在另一个会话中召回它。演示中较早的命中结果，是同一次实验在此前录制的内容：只追加（append-only）的记忆也把那些试演保留了下来。

这件事在多个层面都很重要：

跨机器

将每个智能体绑定到同一份记忆，这样无论你正在使用哪台主机，都能召回历史记录。

跨团队

新队友的智能体可以在加入的第一天就找回数月来的决策，包括那些从未进入拉取请求（pull request）的失败尝试和理由。

伴随开源项目

维护者可以发布某个版本背后的会话，并在 push 时为其命名。可以把它想象成一份可搜索的 CLAUDE.md：它保存了项目为何成为当前样子的历史，而不是要求某个人不断重写的一页文档。任何人都可以使用 --memory 读取公开记忆，并能在 Hub 上发现它。

Hub 已经托管开放权重（open weights）和数据集。funes 则增加了开放工作记忆（open working memory）。它保存项目背后的决策、失败尝试和理由，其他智能体不仅能够查询这些内容，还能追溯到产生它们的会话。

摆脱冗长会话的最低成本方式

压缩是大多数智能体默认采用的方式，而在三种方式中，也是唯一一种结果出现明显分化的：它在一项任务中成功，在另一项任务中却始终没有得到结果。失败时，它生成的摘要抹平了那些至关重要的发现。召回返回的是原始段落本身，因此发现不必经受摘要过程的筛选而得以保留。

在两项任务中，召回都是三种方式里成本最低的：在一项任务中，成本只有书面交接（handoff）的八分之一；在另一项中，则是四分之一。

每根柱子的浅色部分，是开通交接或压缩通道的一次性成本。这些成本会在第一次提问之前支付，并且只计算一次。叉号表示某条通道始终没有到达终点，因此不存在每次成功成本。

告别从零开始

“思考，就是忘却差异，进行概括，抽象出共性。”

——Jorge Luis Borges，《Funes the Memorious》

你的智能体已经写下了这些记录。funes 位于 github.com/huggingface/funes，只需一条命令，就能将这些记录变成下一台机器上的新智能体可以读取的记忆，无论你当时使用的是哪台机器。

构建于开源技术之上

funes 并没有重新发明这些技术。它依赖于足够优秀、可在本地运行的开源嵌入模型、Lance 的只追加数据集及其低廉的增量写入能力，以及 Hub 针对数据集提供的缓存和内容去重（content deduplication）能力。真正的工作，是将这些技术组合成智能体真正能够使用的记忆系统。

funes 本身也是开源的。

无论是安装时遇到问题、召回结果遗漏，还是希望支持新的智能体，都可以提交 Issue。
