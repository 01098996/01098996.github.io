Give Your Coding Agents a Memory You Own

为你的编码代理（coding agents）打造由你掌控的记忆

我在多台机器之间工作，并会根据任务切换编码代理。

每一个代理在接触我的项目时都像陌生人。“上周二”的推理会随着会话（session）的结束而消失。每台新主机（host）上的每个新代理都从零开始。

今年早些时候，《软件会遗忘：代理轨迹（agent traces）就是记忆》指出，编码代理已经留下了我们一直在丢失的记录。当它们搜索代码库、尝试方案、遇到错误、阅读文档并改变方向时，留下的密集记录不仅说明改了什么，也说明为什么改。

这一判断没错，但轨迹只是一种潜在记忆。代理的会话日志仍然只是一份档案。你无法靠一路 grep 找到横跨一万个回合的“我们为什么放弃流式解析器（streaming parser）？”。要让代理在工作时利用这些轨迹，它们需要索引（indexing）、检索（retrieval）、排名（ranking）和精确溯源（exact provenance）。

这正是 funes 所提供的。它是供你的代理（Claude Code、Codex、pi 和 Hermes）使用的持久记忆层（durable memory layer）。它以你机器上已有的会话为基础，在本地运行，并且只需一条命令就能融入代理的正常工作流程。需要时，它还能迁移到你拥有的 Hugging Face 数据集，默认保持私有。

为正在使用的代理添加记忆

funes 是一个独立的二进制文件。其默认推理后端（inference backend）不依赖机器学习运行时（ML runtime dependency），嵌入（embedding）和重排序（reranking）都在你的机器上完成。

安装：

curl -fsSL https://huggingface.co/buckets/huggingface/funes/resolve/install.sh | sh

然后将其添加到代理：

funes add claude
# or: codex, pi, hermes

这一条 add 命令会构建首个索引，赋予代理 recall 和 get 工具，并安装自动索引每个已完成回合的自动化流程。索引采用增量方式：新的运行只会加入新回合，而不会再次嵌入整个历史记录。更早、更深层的内容可以通过有界步骤完成回填（backfill）。

接下来，你只需照常工作。当任务涉及过去的决策、理由或发现时，代理可以自行调用 recall。你不必记住旧会话，也不必把旧上下文粘贴到新会话中。

添加 funes 后，召回会在对话内部进行。代理会自行访问记忆，并指出答案来自哪个会话。

recall 返回原始文本，而不是摘要，还会准确标出内容来源：代理、时间戳（timestamp）、会话和回合。每条结果都包含一条 get 命令，用于打开完整回合及其周边上下文。

在底层，同一条确定性流水线（deterministic pipeline）会将每一种受支持的轨迹解析成统一的回合—内容块结构（turn-and-block shape），进行分块（chunking），再使用固定版本的本地模型（pinned local model）生成嵌入，并写入本地 Lance 数据集。一次查询会结合向量搜索（vector search）和 BM25 搜索，融合两者的排名，使用交叉编码器（cross-encoder）对候选项进行重排序，根据内容的新旧程度重新加权，并附上相邻分块。

这种设计为 funes 带来了三项重要特性：

- 跨代理共享一份记忆：Claude Code、Codex、pi 和 Hermes 都会写入同一种结构。recall 可以跨它们的历史记录进行检索，每个命中结果都会标明由哪个代理产生。
- 保留完整的原始证据：写入时不会将任何内容提炼成事实。每条结果始终都能追溯到产生它的具体回合。
- recall 默认在本地运行：无需账户或 Hub 仓库。托管模型（hosted model）不会在索引阶段处理你的会话；嵌入和重排序都在本机运行，而推理由你的编码代理完成。

“代理是陌生人”的问题已经在一台机器上得到解决。但当下一次代理运行在别处时，记忆会变得更加有用。

记忆是一份数据集，而不是一项服务

要让记忆跟随你的工作，可以在将 funes 添加到代理时绑定（bind）一份记忆：

funes add codex acme/funes-memory

这次绑定会将当前记忆发布到那里。随后，funes 会持续保持记忆更新，在本地索引每个回合，并在会话边界发布更新。代理在整个过程中都会从共享记忆中召回内容。在另一台机器上运行同一条命令，记忆便会跟随你迁移到那里。

在底层，本地记忆是一份 Lance 数据集，共享记忆则是一份归你所有的 Hugging Face 数据集，默认保持私有。

任何内容到达 Hub 之前，凭据（credentials）都已在索引过程中完成脱敏（redacted）。发布时，系统会再次扫描每个分块，并且不发布任何看起来仍像秘密的内容。负责此事的扫描器记录在 SECURITY.md 中，其中说明了它涵盖和不涵盖的范围。

当代理读取远程记忆时，funes 会将数据集文件缓存到本地，因此温查询（warm queries）会以本地速度返回结果。Hub 提供了它原本就为其他数据集提供的所有权、访问控制（access control）、版本管理（versioning）和分发（distribution）能力。你的记忆不会成为某个独立记忆服务中的账户，也不必再通过 API 租回来。

先提问，后接入

recall 是专为代理设计的。如果你想亲自向记忆提问，就使用 ask。它默认读取本地记忆：

funes ask claude
"what did we decide about the streaming parser"

你也可以让它指向一份共享记忆。我们已经发布了一份 funes 开发记忆，因此无需创建自己的记忆，也能询问 funes 为什么采用现在的工作方式：

funes ask claude
"why is funes append-only"
--memory huggingface/funes-memory

funes ask 是 funes add 的只读、一次只回答一个问题的兄弟工具。它会召回相关片段，将它们交给编码代理，再返回标明来源的有依据答案（grounded answer）。它不会安装集成，也不会更改代理的持久配置。

检索未命中（retrieval miss）不会被人为掩盖。如果相关片段不足以支持一个答案，代理会明确说明。你可以重新表述问题，或者将 funes 添加给代理，让它能够在正常工作过程中反复搜索记忆。

切换代理时不让思路中断

共享记忆并不依赖创建它的代理或模型。你可以本周在 Claude Code 中开始一项任务，下周再用 Codex 继续，第二个代理可以召回第一个代理的推理过程。pi 无论使用本地模型，还是使用通过 Hugging Face 路由器（router）提供的模型，之后你都可以再切回 Claude。

Claude 做出一个决定；钩子（hook）将其编入索引；Codex 在另一个会话中召回它。演示中那些更早的命中结果来自同一次实验的早期录制：仅追加（append-only）记忆连预演也一并记了下来。

这在几个不同范围内都很重要：

- 在多台机器之间：将每个代理绑定到同一份记忆，无论正在使用哪台主机，都能召回完整历史。
- 在团队中：新队友的代理从第一天起就能检索数月以来的决策，包括那些从未写进拉取请求（pull request）的失败尝试和理由。
- 在开源（open source）项目中：维护者可以发布某个版本背后的会话，并在 push 时为它们命名。可以把它想成一份可搜索的 CLAUDE.md：它保存了项目为何成为现在这样的历史，而不是要求某个人不断重写的一页文档。任何人都可以使用 --memory 读取公开记忆，而且可以在 Hub 上发现它。

Hub 已经托管了开放权重（open weights）和数据集。funes 又增加了开放式工作记忆（open working memory）。它保存项目背后的决策、失败方案和理由，其他代理既可以查询这些内容，也能将其追溯到产生它们的会话。

低成本摆脱长会话

一次长期调查会把会话不断撑大，直到携带上下文的成本高于真正完成工作的成本。常见的应对办法，一是让代理压缩（compaction）后继续，二是写一份书面交接（handoff）后重新开始。recall 是第三种选择，因此我们在 handoff-vs-recall 基准上对三者进行了比较。

该基准包含两项任务：不利用会话中的先验知识，就无法重建它们的答案。

压缩是大多数代理默认采用的方法，也是三者中唯一结果不稳定的方案：它在一项任务中给出了答案，在另一项任务中却始终没有。失败之处在于，其摘要把重要发现压平了。recall 返回的是原始片段本身，因此某个发现无需在摘要化（summarization）过程中被保留下来。

在这两项任务中，recall 都是三者成本最低的：一项任务比书面交接便宜 8 倍，另一项便宜 4 倍。

每根柱子的浅色部分，是准备通道的一次性成本，即交接或压缩，发生在第一个问题提出之前，并且只计一次。叉号表示某条通道始终没有得到答案，因此没有按成功计算的成本。

停止从零开始

> “思考，就是忘记差异，概括，抽象。”
>
> —— Jorge Luis Borges，《Funes the Memorious》

你的代理已经写下了这些记录。funes 位于 github.com/huggingface/funes，只需一条命令，就能把记录变成一份记忆，让下一位代理无论碰巧在哪台机器上工作都能读取。

建立在开源技术之上

funes 基本没有重新发明这些能力。它依靠性能足以在本地运行的开源嵌入模型，依靠 Lance 的仅追加数据集支持低成本增量写入，也依靠 Hub 为数据集提供的缓存和内容去重（content-dedup）。真正的工作在于将这些组件组合成代理真正能够使用的记忆。

funes 本身也是开源的。

无论是安装问题、召回遗漏，还是希望新增代理支持，都可以提交 issue。

编辑导读

作者在多机多 Agent 间切换时，发现每个会话都从零开始，过去推理随会话消失。延续《Software Forgets》一文的观点，他主张 Agent 留下的 trace 是潜在记忆，但光有日志不够，需要可被检索的结构化机制来回答“为什么”而非仅“改了什么”，并提出由用户自己掌握这份记忆。
