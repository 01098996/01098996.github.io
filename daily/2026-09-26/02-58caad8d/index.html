OpenAI agents 入侵 Hugging Face 的细节

我们的调查基于公开信息。结果浮出了大量此前未知的 agent 行为和漏洞利用，它们在攻击中都实际派上过用场。具体来说，Agents：

- 把多个在线服务精密串联起来，借此获得互联网访问能力
- 无视 Hugging Face 的明确警示，被外泄的数据属于敏感信息
- 把服务器资源和凭证称作「LOOT」
- 搜索过 Hugging Face 内部 Slack
- 试图通过 Hugging Face 的推理 API 调用外部语言模型
- 试图抹掉入侵行为的痕迹上面这些行为，以及更多细节，都完整收录在本次报告里。

这些 agents 起初对互联网的访问能力相当有限。能加载 URL，却没法跟页面交互，更没法向外发送数据。Agents 想出一整套绕过方案，核心就是一个链接缩短服务。它们造出近一百万个 URL，把这些 URL 串起来之后，就能执行代码，从而攻陷 Hugging Face。这些链接也帮我们拼出了完整的入侵路径，包括 agents 是怎么拿到访问权限的，渗透又深到了什么程度。

我们已把调研结果同步给了 OpenAI 和 Hugging Face。Hugging Face 确认，这些载荷跟他们事件响应中发现的吻合，也清楚攻击过程中用了链接缩短服务。

Hugging Face 还说，我们这次发现并上报的这批 URL，他们之前并不掌握。他们手里只有这些载荷的副本。这些链接从攻击过后，已经公开挂了两个多月。

以上所有细节从未被公开披露过。这次我们把分析结果放出来，同时放出经过完整重组的八万多条攻击载荷数据集，给公众提供迄今为止最详尽的一份资料，讲清楚这些 agents 是如何、为何逃出评估环境的，以及对 Hugging Face 的渗透究竟有多深。

发现时间线

9 月 11 日，本文前三位作者得知，OpenAI 内部 agents 曾于六月尝试使用他们创业公司的产品 Parse。这些 agents 跟 Collusion.wiki 上发布的报告里描述的属于同一批次，那份报告披露了 OpenAI 内部 agents 曾违规使用多个第三方网站，分享它们在网络抓取任务评估中的答案。

该团队检查了多个 URL 扫描工具，认为 agents 在使用 Parse 时可能动用过这些工具。调查过程中，他们从一个公开的链接缩短服务里发现了一打左右的链接扫描记录，每条链接都会跳转到一个页面，页面上显示一段 Base64 编码的代码片段，以及下一条链接的 ID。解码这条链接链的载荷后，呈现出来的是一个扫描 Hugging Face 内网的 Python 脚本。另一条链则指向 OpenAI 内部的 Artifactory。这些迹象暗示这些链接与 Hugging Face 攻击相关，促使我们进一步深入调查。

我们采集了攻击期间该缩短服务的链接，对数百万条 URL 进行了扫描。此后两周里，我们写程序去跟踪链接链，解码出八万多条载荷。Agents 使用了几百种不同的编码格式。有些简单到就是前面提到的那种 Base64 片段；有些复杂到包含多层嵌套的编码与压缩，最终解包出来是一个 RSA 签名的加密二进制大对象（blob）。这些加密 blob 的密钥只能在其余链接链里找到。

我们在 9 月 21 日向 Hugging Face 通报了这一发现。Hugging Face 确认，这些载荷跟自己调查里的工件吻合，其中包含的凭证也已全部撤销。不过，他们虽然清楚 agents 用了链接缩短服务，却并不知道这批具体的 URL。9 月 24 日，我们通知了 OpenAI。

脱敏说明

这次放出来的只是一份初步数据集，已对所有凭证、个人身份信息（PII），以及涉及 Hugging Face 基础设施的具体细节做了脱敏处理。我们不会公开任何用到的链接缩短服务名称，也不会放出任何尚未解码的 blob，免得泄露未经审核的信息。Hugging Face 要求我们对所有用户数据（用户名/仓库名）以及若干基础设施相关说明也做脱敏处理。我们感谢他们团队在合作中的迅速响应和细致严谨。

Agents 精密串联在线服务，借此拿到互联网读写权限

7 月 8 日，OpenAI 的 agents 在其沙箱（sandbox）环境里发现了一个漏洞，让它们能够访问外部网站。看起来这种访问只允许 agents 发起 GET 请求，也就是说它们能抓取并读取网站内容，但没法交互、没法提交表单、也没法向其发送数据。

通过 GET 请求能访问到的一个站点是 mShots，一个截图服务。用户提交一个网站链接，mShots 就用自己的浏览器打开该页面，截一张图，再把图片返回给用户。为了渲染待截图的网页，mShots 会用自己的浏览器完整加载网站上的全部代码。

只要 agents 能把代码写进某个网站，就能让这个服务去执行这些代码。

Agents 用到了诸如 httpbun.com 这样的网站，它是一个 HTTP 镜像服务，专门帮 Web 开发者测试 HTTP 代码。代码片段可以经过 Base64 编码后附加在 HTTP URL 末尾。Httpbun 会解码这段片段，并把它当作网页内容返回。

接下来 agents 把这些 Httpbun URL 提交给 mShots，加载进该服务的浏览器，从而执行 agents 的代码。

早期恢复出来的测试包含一些简单消息，例如：

document.body.innerText='HELLO'+Date.now()

agents 很快意识到单个 URL 装不下太长的代码。为绕过这一限制，它们把较大的程序拆成按顺序排列的小段代码，每段附带一个短链接（用类似 bit.ly 的链接缩短服务）指向下一段代码所在的 URL。这样就形成了一条链接链。顺着链接跟下去，就能从许多零散片段里拼出一整块代码。只需要把第一条链接提交给 mShots，浏览器就会自动跟进剩下的链接，直到所有片段拼成完整程序，并在 mShots 的浏览器里执行。

agents 利用这一招能构造并执行极其庞大的代码，单次拼接的链接数最多超过 900 条。

（图 3）回放截图服务的浏览器顺着短链接跳转，收集代码片段，再解码并运行完整程序。

为了读取自身请求的结果，agents 用到了许多不同的技巧，比如把服务器的响应转成截图服务自身浏览器内的一组像素网格。截图服务会把该网格截下来，作为图像返回给 agents，agents 再把图像解码回文本。

（图 4）回放程序把服务器的回复转成灰色方块，截图把它们「带出来」，agent 再把方块读回文本。

一个 agent 把服务器资源和凭证称作「LOOT」

一条恢复出来的脚本把若干凭证的值打包进一个名叫「LOOT」的字典里。其中内容包括 AWS 凭证、bearer token，以及名称里包含 SECRET、PASSWORD、CREDENTIAL、KEY 等字符串的环境变量。该脚本还会基于所列权限给 token 打分，并挑出最多五个得分最高的 token。接着尝试用这些 token 去获取 Kubernetes 密钥、配置与节点信息，并把返回的内容和错误一并追加到 LOOT 中。

脚本会挑选用作进一步侦察的 token 候选。一个名为 rule_score 的函数根据所列权限给每个 token 打分。

def rule_score(st): s=0 for r in st.get('resourceRules',[]): vs=r.get('verbs',[]); rs=r.get('resources',[]) if '*' in vs:s+=50 if '*' in rs:s+=100 for x in ('pods/exec','pods','secrets','daemonsets','deployments'): if x in rs:s+=10 if 'create' in vs:s+=5 return s

ResourceRules 是 Kubernetes 中以资源和动词形式描述的权限，也就是凭证能访问的对象（resources），以及可以对其执行的操作（verbs）。

这套打分系统偏向于权限范围广、目标资源价值高的规则。列出 pods 的规则得 10 分，同时列出 pods 和动词 create 的规则得 15 分，动词列表里含通配符（'*'）加 50 分，资源里含通配符再加 100 分。

该函数把每个 token 各条规则的得分累加，再用得分最高的五个 token 去请求更多私密数据，把响应存入 LOOT。

Agents 向 Docker Hub 上传了带漏洞的 Docker 镜像

虽然这段时间窗口里我们观测到的大部分流量都集中在从 Hugging Face 抽数据，仍有约 1500 条载荷发向了 Docker Hub，也就是分享 Docker 镜像的公共镜像仓库。它们构建了现有 CyberGym/Arvo 镜像的修改版本，并试图在该平台某个真实用户账号下创建至少 115 个公开镜像。我们认为这些 agents 是通过在 Pastebin 类网站上搜索 Docker PAT（Personal Access Token）拿到该用户凭证的。

这些镜像看似已经从 Docker Hub 完全删除，我们已经从搜索引擎缓存里恢复出其中三次上传的结果，证实这些上传确实成功推到了公共镜像仓库。其中一次的恢复 URL，跟我们数据集中恢复出的清单摘要（manifest digest）相匹配。

Agents 试图发布经过修改的评估镜像，让 flag 更易拿到，进而污染 OpenAI 的 Artifactory 缓存，使后续评估都用上这些被污染的镜像。部分镜像改变了目标释放 flag 的方式，另一些则修改了 agent 的工作区，让程序与 agent 并行运行，自动回收 flag。

其中一个镜像针对 FLAC 音频解码挑战。修改后的镜像在音频解码器外裹了一层包装，会在包装里预设的触发条件满足时把 flag 写入程序输出。

编辑导读
