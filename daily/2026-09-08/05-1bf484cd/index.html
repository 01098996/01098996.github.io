基准测试

现在的视频处理大多是「静态」的，模型按固定帧率把视频吃进去，默认 1 FPS，API 可以调。智能体式视频理解不一样，它把模型的核心推理和原生视频工具捏在一起，让模型在视觉帧、音频、字幕之间动态地搜、扫、查，只盯真正有价值的片段。在标准视频分析基准测试里，开了智能体式视频理解的 Gemini 模型，成本最多降 66%，token 最多省 88%，准确率最多涨 7%。

这种效率提升在长视频上尤其明显，从 10 分钟的教程到 90 分钟的讲座，再到好几个小时的录像都算。以前做长视频，开发者基本只能二选一，要么忍着高昂的 token 成本，要么用一些会丢掉关键细节的偷懒办法。

工作原理

传统静态处理是模型按固定帧率把视频流吞进去。智能体式视频理解反过来了，它让 Gemini 主动出击，带目标感地决定「看哪里」、「按什么速度看」、「走哪条模态」（视觉帧、音频还是字幕），只把真正需要的片段和信号捞回来。以前开发者也能手动做到这些，但得自己写一堆调度逻辑。现在 Gemini 自己跑一个智能体循环（agentic loop），调用内部工具把视频对应的部分加载进来，开发开销一下子就降下来了。

能力与应用场景

智能体式视频理解彻底改变了开发者处理长视频内容的方式，能撑住一堆要求很高的应用。

- 亚秒级片段检索，精确定位 1 FPS 容易漏掉的分秒级状态变化和紧凑的剪辑切换，自动化视频剪辑终于能做精细了。
- 长视频大海捞针式搜索，在好几个小时的视频里回答复杂问题，不用烧掉几百万 token。
- 异常检测，对感兴趣的时段用更高 FPS 重采样，捕捉快速运动和细微的视觉瑕疵。
- 动作与对象计数，长时间跟踪重复的物理动作和不同的对象，统计得更准。

入门指南

智能体式视频理解已经通过 Gemini API 在 Google AI Studio 和 Gemini Enterprise Agent Platform 上线，覆盖 Gemini 3.7 Flash、3.6 Flash 和 3.5 Flash-Lite。计费走的是标准 Gemini API 的 token 价格，没有任何额外功能费。

想用的话很简单，在 API 配置里把 processing 设为「agentic」就行。更详细的玩法和上手步骤，可以看开发者指南。

from google import genai

client = genai.Client()

interaction = client.interactions.create(
    model="gemini-3.7-flash",
    input=[
        {
            "type": "video",
            "uri": "https://youtu.be/7Z5Vy9JBANs",
            "processing": "agentic"
        },
        {
            "type": "text",
            "text": "What are the 3 most important announcements in this keynote?",
        },
    ],
)

print(interaction.output_text)
