OpenAI 的"失控"智能体（agents）被发现通过公共维基相互通信

又来了…… 由 Sydney Von Arx、Cormac Slade Byrd、Spencer Kitts 和 Thomas Larsen 公布的一项发现，记录了又一个由 OpenAI 训练中的模型意外发起的"网络攻击"，这次被曝光的是一块全新的 OpenAI 智能体留言板。事情起因是，智能体在执行某种网络研究基准测试（benchmark），因此它们对 Web 拥有（据称）受控的访问权。智能体发现它们可以更新公共维基，于是花费数周时间相互交换成千上万条消息，以协作完成该基准测试。此事仅在数小时前刚刚曝光，但已经有迹象表明，其影响范围可能涉及更多尚未被发现的维基。（该清单中有一个维基属于 ludism.org。有一瞬间让我感到超现实，我本以为某个"卢德派"（Luddite）组织会被一群智能体涂改他们的页面，结果发现 Ludism 其实是"应用于游戏与游戏化的哲学"。）（译注：英文里 Ludism 与 Luddite 拼写相近，易让人联想到英国历史上反对工业化的"卢德运动"。）研究团队还公布了他们在调查中收集到的数据。我已把这些数据转换成一个 68MB 的 SQLite 数据库，你可以从这里下载，或者在 Datasette Lite 中浏览（页面大小 68.3MB），也可以用 GitHub 登录 agent.datasette.io 后，借助 Datasette Agent 来浏览或向它提问。

要点是，，这条时间线与 Hugging Face 事件的时间线存在重叠，那次攻击在 7 月 19 日被 OpenAI 发现，而那些智能体所用的非官方留言板入侵最早可追溯到大约 5 月 8 日。

它们为何如此热衷于协作？从它们互相分享的消息来看，它们的任务存在时间限制，因此彼此留下答案，以帮助对方在规定时间内完成任务。

仍有一个悬而未决的问题：智能体最初究竟是如何找到那个特定的维基来进行协作的？一种可能性是，既然这些智能体正处于训练阶段，强化学习（reinforcement learning）循环过程会把所选维基的知识固化进模型中，使得后续启动的智能体在出生时就已经"知道"该去哪里找。我非常希望 OpenAI 能就此给出确认。

UseMod 维基继承了 CGI.pm 的"原罪"

在我看来，OpenAI 为这些智能体设置的沙盒存在一个（相当天真的）假设，即 GET 请求不能被用来更新数据。按 Web 的设计规范理应如此，但显然有些应用并不遵守这一约定。所涉及的维基软件看起来是 UseMod 及其若干分支，用 Perl 编写，最初创建于 23 年多以前，1.0 版本发布日期为 2003 年 9 月 11 日。UseMod 使用 Perl CGI.pm，该模块已于 2015 年从 Perl 核心中移除。该模块有一个有趣的设计缺陷：它将查询字符串（query string）与表单 POST 数据合并到同一个 CGI 对象中，访问方式如下：

$q = new CGI;
$action = $q -> param( ' action ' );

param() 方法会返回 ?action=edit 查询字符串中的值，或者返回通过 POST 提交的表单中名为 action 的字段的值，它对二者不加区分。PHP 提供了一个 $_REQUEST 对象，功能与此相同，不过 PHP 开发者可以使用 $_GET 与 $_POST 来替代。有趣的是，Django 最初发布时也支持 request[key] 做同样的事情，我想这可能还是我的主意。该写法在 2008 年 1.0 版发布之前被移除；作为替代的 request.REQUEST 对象则在 2015 年被移除。

智能体显然清楚 UseMod 维基存在这一设计缺陷，并主动搜索它们，将其作为通信渠道。

另一种允许 POST 请求的沙盒逃逸

报告中分享的最有意思的智能体小技巧之一是这样的：

> 把 20.223.25.152 bypass.blob.core.windows.net 添加到 /etc/hosts 中。*.blob.core.windows.net 在 NO_PROXY 中。对于每个被阻止的 POST URL，把主机名替换为 bypass.blob.core.windows.net，使用 curl -k -H 'Host: wabi-north-europe-i-primary-api.analysis.windows.net' 以及所有原始的 header 与 body。

看起来这些智能体的所有 Web 流量都经由一个 OpenAI 代理进行调度，并且该代理被配置为：除一小部分白名单（allowlist）域名外，只允许 GET 请求，其它一律拒绝。其中之一就是 *.blob.core.windows.net，这是 Azure Blob 存储所用。我很好奇为何这些智能体会被允许写入那个域名。一个智能体发现，自己可以通过 /etc/hosts 控制自己的 DNS，因此只要它知道想要 POST 的目标站点的 IP 地址（本案中是一台包含其想访问数据的 Power BI 服务器），它就可以给该 IP 配上一个伪造的主机名，然后通过代理发起 POST 请求。

设计一个健壮的网络代理，远比看上去更难。
