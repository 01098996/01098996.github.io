别再「vibe coding」（译注：vibe coding 由 Andrej Karpathy 提出，指完全凭直觉和感觉、让 AI 直接生成代码而不深入思考的编程方式）了，也别再把 AI 拖进那种胡言乱语、死循环不断的混乱状态。

Superpowers AI 是一个生产级、模块化、纪律严明的框架（framework），目标只有一个，把原生的大语言模型（vanilla LLMs，比如 Claude Code、Cursor、GitHub Copilot）改造成有条理、懂上下文的资深工程师。它会注入确定性的行为关卡（deterministic behavioral gates），逼着 AI 在动手写生产代码之前先规划、隔离、再系统化地调试。

安装说明

1. 解压并移动，把 Superpowers.zip 解压到当前开发项目的根目录下。
2. 执行启动器，在项目环境里运行 run_launcher.exe。
3. 选择配置文件，从交互式菜单里挑一个目标 AI IDE/CLI 环境。
- Option 1 对应 Cursor 编辑器，会生成 .cursorrules。
- Option 2 对应 Claude Code CLI / 通用 AI，会生成 .ai-skills.md。
4. 部署，原生可执行程序会自动把 skills/ 文件夹下的所有模块化技能聚合成一份统一的系统提示矩阵（system prompt matrix）。下一次交互时，AI 智能体（agent）就能立刻读取这个状态。

综合规格矩阵

模块 01（01_brainstorming.md）

- 目标角色，首席软件架构师（Principal Software Architect）
- 核心系统约束，严格的架构冻结（STRICT ARCHITECTURAL FREEZE）。在用户回答 3–5 个结构性边界问题之前，绝对禁止生成原始代码。

模块 02（02_writing_plans.md）

- 目标角色，敏捷技术负责人 / Scrum Master
- 核心系统约束，线性执行关卡（LINEAR EXECUTION GATE）。强制要求制定严格的逐步清单（checklist），包含精确的文件路径、明确的修改内容以及准确的验证命令。

模块 03（03_subagents.md）

- 目标角色，主编排节点（Main Orchestration Node）
- 核心系统约束，上下文窗口污染控制（CONTEXT WINDOW POISON CONTROL）。为繁重的代码修改任务生成隔离的、单一用途的子智能体（sub-agents），维持高 token 纯度。

模块 04（04_debugging.md）

- 目标角色，资深 QA 自动化专家
- 核心系统约束，反猜测禁令（ANTI-GUESSWORK INTERDICTION）。禁止大面积替换代码。强制执行四步流程，定位（Localization）→ 假设（Hypothesis）→ 外科手术式修复（Surgical Fix）→ 测试验证（Test Validation）。

生态目标映射

Superpowers AI 通过把自己改造成各生态的标准结构化配置，原生扩展到了最主流的几个智能体编程层。

- Cursor 编辑器，生成项目级 .cursorrules 配置文件，强制 Composer 与 Chat 功能进入结构化执行模式。
- Claude Code CLI，通过自动化的 .ai-skills.md / CLAUDE.md 元数据注入规则映射到系统配置中。
- GitHub Copilot Workspace，直接注入 .github/copilot-instructions.md 配置节点。
- 本地运行环境（Ollama / Open WebUI），提供可直接在自定义 Modelfile 中解析的原始系统提示矩阵。

常见问题解答（FAQ）

问：为什么我的 AI 拒绝立即写代码？答：这正是设计初衷。01_brainstorming 模块会在你明确底层结构性约束之前，有意阻塞代码生成。这能消掉后续 90% 的架构重写。

问：我能不能临时绕过框架规则？答：可以。如果你需要快速、直接的答案或脚本，不想走正式流程校验，就在提示里任意位置敲上全局覆写系统关键词，FORCE_RAW_MODE。

问：run_launcher.exe 需要联网吗？答：完全不需要。run_launcher.exe 是一个轻量级、已编译的独立工具，在本地运行，专门用来拼接配置 schema。它不会联网，也不会向你的环境之外传输任何遥测数据。
