typesafe-mcp：把 Typesafe AI 的 Jev 模型接入代理的 MCP 连接器

itsmostafa/typesafe-mcp

当 agent 需要做是非判断、路由决策或严重程度评级时，通常会让一个大语言模型（LLM）来回答，然后再去解析自然语言文本，寄希望于格式不会出错。答案并没有附带概率，agent 也无从分辨一个胸有成竹的"是"和一次抛硬币的结果。

解决方案：evaluate 暴露了一个工具 evaluate，它把状态（state）和带类型的问题一起发给 Jev，并返回附带概率的结构化答案。无需解析，也不用维护 prompt 格式。

evaluate setup mcp 一步就能把它接入 Claude Desktop、Claude Code 和 Codex；evaluate setup pi 则为 pi 安装等价的扩展。

快速上手

1. 安装

（macOS 和 Linux，amd64 与 arm64）：

curl -fsSL https://raw.githubusercontent.com/itsmostafa/typesafe-mcp/main/install.sh sh

默认安装到 ~/.local/bin。如果该目录不在你的 PATH 中，可以执行 export PATH="$HOME/.local/bin:$PATH" 添加。如果你已经装了 Go，也可以直接运行 go install github.com/itsmostafa/typesafe-mcp/cmd/evaluate@latest。运行 evaluate update 即可原地升级。

2. 在你的 agent 中注册

先在 TypeSafe 控制台申请一个 key，然后执行：

TYPESAFE_API_KEY=your-key evaluate setup mcp

已经在用 OpenRouter？也可以直接用 OpenRouter 的 key，evaluate 会通过 OpenRouter 的 Decisions 端点来路由，费用计入你的 OpenRouter 账户：

OPENROUTER_API_KEY=your-key evaluate setup mcp

如果两个 key 都设置了，以 TYPESAFE_API_KEY 为准。OpenRouter 的 Decisions 端点目前仍在 /api/alpha/ 路径下，未来可能调整。

用的是 pi？它没有 MCP 客户端，所以 evaluate 提供了一个 pi 扩展：

evaluate setup pi

这会写入 ~/.pi/agent/extensions/evaluate.ts，把 evaluate 注册为 pi 的原生工具，并由它代为与 evaluate mcp 通信。在 pi 中运行或重新加载即可生效。与 MCP 客户端不同，文件里并没有写死任何内容：扩展会从 pi 运行时的 shell 中读取你的 key。

3. 让你的 agent 回答一个判断题

> "Use evaluate to decide whether this ticket is urgent and which team should own it: Help! My payouts have been failing for 3 days."

agent 会用以下参数调用 evaluate：

{
  "state": "Help! My payouts have been failing for 3 days.",
  "questions": {
    "is_urgent": {
      "type": "noul",
      "instructions": "Does this convey urgency?"
    },
    "department": {
      "type": "choice",
      "instructions": "Which team should handle this?",
      "criteria": {
        "billing": "Payments, refunds",
        "technical": "Bugs, outages",
        "sales": "Pricing"
      }
    }
  }
}

拿到的是原始的响应 JSON，每个答案都放在你指定的 id 下面。

你能得到什么

一条命令搞定多客户端配置。 evaluate setup mcp 会在 Claude Code（用户作用域）和 Codex 的 CLI 在 PATH 中时自动注册它们，并在 Claude Desktop 已安装时注册它。shell 中所有 TYPESAFE_* 变量都会被一并带入，OPENROUTER_API_KEY 也不例外。重新运行即可更新。evaluate setup pi 用于安装 pi 扩展。

你的代码可以基于答案做分支判断。 三种问题类型：noul（某条件成立的概率）、choice（从一个映射中选一个选项）、score（在有序等级中的位置）。

速率限制已为你处理。 遇到 429 和 529 响应会按指数退避策略重试。其他 API 错误会作为工具错误返回给 agent，agent 可以读取并据此采取行动。

一次调用，多个问题。 对同一状态批量提出相互独立的问题，它们会并行执行。

开箱即用，agent 就能写好问题。 服务器会把使用指引（问题要聚焦、状态用 JSON、提供"无匹配"选项、给出证据而非结论）一并发给客户端，因此 agent 不需要额外提示也能写出更好的问题。

单一静态二进制。 无运行时，无需 Node，无需 Python。evaluate update 会从经过校验和验证的发布版本原地升级。只读工具，请求超时 60 秒，响应大小上限 16 MiB。

关于 TypeSafe

TypeSafe 构建 System One 模型：像编程原语一样使用的小型 AI 智能单元。它们不生成文本，而是把自然语言和应用状态转成带类型的判断和概率，供代码组合使用。Jev 就是其中之一。

编辑导读

该项目是一个 Go 编写的 MCP 连接器，旨在把 Typesafe AI 的 Jev 判别模型作为工具直接暴露给 AI 代理，从而在工作流中接入低成本的判别判断。仅仓库描述可用，具体鉴权方式、调用接口与延迟表现有待核实。

为什么读通过 MCP 把判别模型接入代理，是观察 Jev 生态落地的最直接样本。
