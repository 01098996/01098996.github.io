openchatx-mcp：把ChatGPT变成本地代理运行时

XiaoPuOuO/openchatx-mcp

OpenChatX 是一个开箱即用、完全可定制的本地智能体（agent）平台。它内置编程级的文件与 Shell 工具、计算机控制、MCP（Model Context Protocol，模型上下文协议）聚合、Skills（技能）、Rules（规则）、Projects（项目）、Tasks（任务）、Subagents（子智能体）、跨会话总结（cross-session Summaries）等能力。所有这些都通过一个官方的 ChatGPT MCP 连接对外暴露，并提供 Toolboxes（工具箱）来定制智能体的工作方式。

Important OpenChatX 通过常规的 ChatGPT Chat 运行，不消耗你的 ChatGPT Work 或 Codex 智能体额度。就算 Work 或 Codex 额度用完了，只要普通 Chat 用量还在，OpenChatX 照常可用。

Caution OpenChatX 以本地用户权限运行。受信任的 ChatGPT 调用方可以执行命令、编辑文件、使用已连接的 MCP 服务器，并控制受支持的应用程序。

工作原理

OpenChatX 走的是 OpenAI 文档化的 MCP 集成路径，官方 MCP，零逆向工程。它不逆向 ChatGPT、不调用未公开的 ChatGPT 后端端点、不复用浏览器会话 cookie，也不拦截 ChatGPT 流量。

连接方式是这样的。OpenChatX 在你的机器本地跑一个标准的 MCP 服务器。

OpenAI 官方的 tunnel-client 向 OpenAI Secure MCP Tunnel 建立一条出站的 HTTPS 连接。本地 MCP 服务器不需要公网入站端口。

ChatGPT 通过受支持的 ChatGPT Developer Mode（开发者模式）/ MCP app 流程，作为自定义 MCP 应用连接到该隧道。

ChatGPT 调用工具时，Secure MCP Tunnel 把 MCP 请求转发到本地的 OpenChatX，再通过同一官方通道返回 MCP 响应。

随后 OpenChatX 把请求路由到本地工具、你的计算机、已连接的 MCP 服务器、Skills、Rules、Projects，或显式配置的 Subagents。

ChatGPT 仍是模型与规划者。OpenChatX 是本地的工具与运行时层；它不会冒充 ChatGPT，也不会替 ChatGPT 发起隐藏的模型调用。

OpenChatX 中配置的 Runtime API key 用于官方的 Secure MCP Tunnel 控制面，并存储在操作系统的凭据存储里。它既不是抓取来的 ChatGPT 凭据，也不是绕过 ChatGPT 受支持接口的取巧方案。

官方参考：

- OpenAI Secure MCP Tunnel：https://developers.openai.com/api/docs/guides/secure-mcp-tunnels
- ChatGPT Developer Mode 与 MCP apps：https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt

把 OpenChatX 接到 ChatGPT

OpenChatX 使用 OpenAI Secure MCP Tunnel。桌面应用负责管理本地运行时和内嵌的 tunnel-client，你只需要创建一次隧道。

1. 创建 ChatGPT MCP 应用

Developer Mode 开关目前在 ChatGPT 中似乎缺失。

部分用户反馈不开 Developer Mode 也能创建 MCP 应用，所以现在请跳过这一步，直接走下面的 Plugins 流程。

打开 Plugins，点 Create app，再选 Create MCP app。

填好应用名称和描述，把连接类型切到 Tunnel，点 Create tunnel。

2. 在 OpenAI Platform 创建隧道

打开 OpenAI Platform 的 Tunnels 页面
https://platform.openai.com/settings/organization/tunnels点 Create tunnel，然后配置：

- Name，例如 OpenChatX Tunnel
- Description，例如 OpenChatX Tunnel
- Organizations，选拥有该隧道的组织
- ChatGPT workspaces，选将使用 OpenChatX 的 ChatGPT 工作区点 Create。

创建完成后，复制那个 tunnel_… 开头的 ID。这个 ID 等会儿要填进 OpenChatX Desktop。

3. 创建 Runtime API key

打开 OpenAI Platform 的 API Keys 页面
https://platform.openai.com/settings/organization/api-keys为 OpenChatX 隧道运行时新建一个 secret key。起个像 OpenChatX Runtime Key 这样的名字，日后好认。

Secret 一显示就复制下来。别提交到 Git，也别贴到聊天里。

4. 连接桌面应用

打开 OpenChatX Desktop → More → Connect Tunnel…

填：

- Tunnel ID，第 2 步的 tunnel_… ID
- Control-plane API key，第 3 步的 Runtime API key桌面应用把 API key 存在操作系统的凭据存储里：

- macOS：Keychain
- Windows：Credential Manager

5. 完成 ChatGPT MCP 应用

回到 ChatGPT，选中新创建的 openchatx（tunnel_…）隧道。

把认证方式设为 No authentication。

阅读并接受 custom MCP 风险告知。

点 Create。

如果想让 ChatGPT 使用 OpenChatX 工具时不再每次都弹确认，可以把 OpenChatX 应用的权限设为 Allow all tools。

常用链接：

- OpenAI Secure MCP Tunnel 指南：https://developers.openai.com/api/docs/guides/secure-mcp-tunnels
- OpenAI Tunnels 设置：https://platform.openai.com/settings/organization/tunnels
- OpenAI API keys：https://platform.openai.com/settings/organization/api-keys

OpenChatX 给 ChatGPT 的能力

| 能力 | 作用 |
| --- | --- |
| MCP Servers | 通过一个 OpenChatX 连接接入本地或远程的 MCP 服务器 |
| Toolboxes | 添加或管理自定义的 TypeScript 工具 |
| Skills | 便携式的 SKILL.md 工作流，只在需要时加载 |
| Rules | 持久化的 .mdc 规则，支持 Always / Auto Attached / Agent Requested / Manual 等模式 |
| AGENTS.md | 可编辑的 start_here 模板，带运行时占位符 |
| Projects | 把 ChatGPT 的工作绑定到现有文件夹，无需挪动文件 |
| Summaries | 通过 UUID 交接，把跨多个全新 ChatGPT 对话的长时间任务延续下去 |
| Subagents | 把任务委派给显式配置的模型配置文件（model profile） |
| Capability Store | 安装内置能力，或浏览/安装 GitHub 上托管的社区能力 |
| Dashboard | 管理会话、临时 Summaries、工具、Skills、Rules、MCP 服务器、Projects、状态等 |外部 MCP 和 Toolbox 的 schema 保持懒加载（lazy），这样 ChatGPT 正常的工具上下文不会变大。

跨会话总结

OpenChatX 有一项很关键的差异化能力。长时间的 Agent 工作可以跨越 ChatGPT 对话本身延续下去。当某次对话最终撞到实际的上下文上限时，OpenChatX 提供一个交接层，省得你手动重建任务。

编辑导读

该TypeScript项目通过单一MCP连接，让ChatGPT变身本地代理运行时。用户可让ChatGPT操作电脑、调用本地工具、发现MCP服务器，甚至将任务委派给本地自有模型运行，专注macOS平台，为云端AI接入本地工作流提供轻量方案。

为什么读它打破了ChatGPT只能作为云端对话工具的限制，展示了通过MCP协议桥接云端与本地工作流的可行路径。
