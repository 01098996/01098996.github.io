下一会话（session）可以信任的内容。本工具包就是这一层，里面有技能、一份章程、Codex 能自己跑起来的安装程序，还有一个默认拒绝（fail-closed）的校验器。

克隆后告诉 Codex，让它阅读本工具包中的 INSTALL.md，按其指示在本机装好记忆系统。

没有 GUI。安装程序是给智能体（agent）跑的。安装可逆。没有 wiki？那就只启用 project-memory 技能。

它为何属于 Codex 生态

当仓库已经知道自己该如何被维护时，Codex 才最强。本工具包就是这份契约，写成智能体能安装、遵守并自证的形式。

| Codex 维护者工作 | 本工具包使之自动化的工作 |
|---|---|
| 不重读整棵树就能审 PR | HOT 快照（snapshot）+ WARM rg（ripgrep），不是把 docs/ai/ 全部倒出来 |
| 保持发布说明与运行手册准确 | 对 docs/ai/ 做有界控制，配合 replace-guards（替换保护），而不是只追加的笔记 |
| 在同一仓库的二次会话中存活 | 交接只用一页，就地替换，git 即账本 |
| 不让密钥流入「记忆」 | 章程 + 清洗器（sanitizer）关卡，写入方被禁止存密钥 |
| 之后升级记忆系统 | 基于回执（receipt）的哈希比对，你的修改被保留，旧工具包归档而非销毁 |它是一流的 Codex 基础设施。AGENTS.md 段落、Codex 技能、智能体可执行的 INSTALL.md，还有作为验收标准的 VERIFY.md，整体形态跟一套严肃的维护者工具链无异，不是那种粘贴一次就丢的提示词包。

它消除的失败模式

智能体要么在不同会话间遗忘项目，要么靠往交接笔记和变更日志里追加内容来「记住」。这些文件没有上限。下一会话在开始任何真正工作之前，会先吃掉几万 token，有时甚至几十万，全在消化昨天的残渣。

那不是记忆，是带着 git 历史的上下文污染。

| 朴素的智能体笔记 | 本系统 |
|---|---|
| 只追加的交接，无上限 | 一页快照，就地替换 |
| 平行的变更日志文件 | Git 提交即账本 |
| 把 docs/ai/ 全部塞进上下文 | 热 / 温 / 冷（HOT / WARM / COLD）分层，多数文件不会被读取 |
| 升级时静默覆盖 | 基于回执的哈希比对，你的修改得以保留 |
| 「装上了，大概吧」 | VERIFY.md，用退出码（exit code）做断言，不靠感觉 |

你将得到

一份章程，不是感觉。SYSTEM.md 就是规范，里面有分层、字节预算、来源署名（attribution）、replace-guards（替换保护），还有「禁止写入密钥」。技能不能凌驾其上。

智能体原生（agent-native）的安装程序。INSTALL.md 是给 Codex 跑的，步骤包括适配路径、合并全局规则、启用仓库、写入机器回执、回滚。

校验器，不是清单。VERIFY.md 是带真实退出码的断言。工具包字节由 SHA256SUMS 锁定。

一份技能源，两个 harness。Codex 持有源文件，第二个 harness 拿到的是符号链接（symlink）。不分叉副本。

默认拒绝的升级。全新安装 / 升级 / 迁移是不同的契约。旧工具包先被封存。

密钥卫生即边界。可选的 coach 路径会在学习记录抵达中央 wiki 之前先做清洗。回归测试套件的存在，是因为这套系统曾被视为一道安全关卡。
