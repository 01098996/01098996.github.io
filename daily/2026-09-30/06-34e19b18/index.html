什么是 iCode？

让截图自己说话。

请使用现代终端（terminal）。

iCode 在 Windows Terminal（Windows）或 Ghostty（macOS 和 Linux）这样的现代终端中效果最佳。

主页 智能体（agent）、模型、审批模式和会话一览无余，智能体（#）、模型（$）、命令（/）、文件（@）和 shell（!）距输入栏仅一键之遥。

对话 回复在终端中以丰富的 Markdown 渲染，包含图表。

工作流 逐节点查看工作流的运行，每个智能体节点的模型、工具调用（tool call）和 token 消耗都一目了然。

智能体 智能体是配置而非代码：指令、工具、子智能体（sub-agent）、技能（skill）、MCP 服务器和记忆，都可在同一处（F2）编辑。

模型 来自不同提供商的模型配置文件（profile）并列展示，可在对话中途切换（F4）。

差异 智能体变更的每个文件，可逐轮或一次性查看，支持统一视图或分屏视图。

回滚 选择某一轮，预览将回退的文件变更，然后丢弃其后的对话。

轨迹 时间和 token 流向（F12）：模型、工具与等待的占比，每轮的明细，以及 token 和缓存使用情况。

一轮中每次模型调用、钩子（hook）和工具调用，都按时间线依次铺开。

Shell Shell（!）是一个真正的终端，全屏程序在其中就地运行，每次按键都直接转发给它：图中即为 htop，在 iCode 里，iCode 里，iCode 里。

如何运行

uv 是唯一的先决条件，它会为你准备 Python 3.14。从检出目录开始：

uv sync --extra all

注意，不是裸的 uv sync，也不是 --all-extras。

./scripts/fetch_rg.sh

下载预打包的 ripgrep；Windows：.\scripts\fetch_rg.ps1

uv run icode

uv run chrys 启动的是同一个东西（Chrys 是我们的代号）。

iCode 不附带任何模型配置文件，因此首次启动时请按 F4 添加一个。

用户指南

在 iCode 内按 F8 打开内置的用户指南，这是使用它的完整教程。

同样的页面也存放在 docs/ 下，提供英文和简体中文版本。

隐私

iCode 不收集你的数据。它没有遥测（telemetry）、分析（analytics）或崩溃报告（crash reporting），默认情况下不向我们或任何其他第三方发送任何内容，包括使用数据。iCode 本身发送的内容只会去往你配置的目的地：你添加的模型提供商、你的智能体使用的 MCP 服务器，以及你设置的钩子（hook）或 OpenTelemetry 导出。网页工具默认关闭。如果你为某个智能体启用了它们，其搜索查询会发送到你配置的搜索提供商；若你未配置，则发送至 Exa 的公共搜索服务（mcp.exa.ai），并且它读取的页面直接从对应网站请求。你和你的智能体运行的 shell 命令、技能脚本和工作流本身就是程序，拥有你的网络访问权限，因此它们发送什么由它们自己决定。你的数据只属于你，我们尊重你的隐私。

法规合规

iCode 仅是一个用于编排智能体和工作流的工具。它不包含也不提供任何 AI 模型；它使用的每个模型都是你自行接入的。当你将 AI 模型集成到 iCode 中用于特定的业务或工程用途时，你须自行承担该用途依据《欧盟人工智能法案》（EU AI Act，Regulation (EU) 2024/1689）以及任何其他适用法律或监管框架所要求的合规义务。
