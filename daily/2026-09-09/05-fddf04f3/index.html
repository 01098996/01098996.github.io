1Password 通过 Codex 将工程生产力提升 21%

1Password 的工程师使用 Codex 快速构建新功能和内部工具，在保持严格安全策略的同时达到生产就绪状态。

- 20.9% Codex 用户群组中测得的生产力提升
- 10.9% 拉取请求（pull request）周期时间中位数下降
- ~90% 跨多服务的复杂生产问题的排查时间下降
- $0.8M Codex 估算的年度工程产能价值1Password 已将 Codex 集成到软件交付全生命周期中，压缩从规划到上线的时间，从而以极快的速度构建新功能。1Password 团队将其核心用户群组的拉取请求周期时间中位数缩短了近 11%，并将工程生产力提升了近 21%。

基于工程团队取得的成效，1Password 领导层正在把 Codex 的使用范围扩展到其他职能，让财务、市场等团队也能自行构建工具和功能。整个过程中，1Password 始终维持其严格的安全标准，确保速度提升与数据保护之间不存在取舍。

"令我们许多工程师真正大开眼界的是，规划到能在生产环境中看到功能上线之间的周期大幅缩短了。"，1Password 首席技术官 Nancy Wang

用 Codex 一次性完成新功能

1Password 正借助 Codex 让创意更快从规划走向实现，帮助工程师把清晰定义的用户故事转化为可运行的功能。

"以前，你接到一个项目，得考虑如何把它拆分成不同的冲刺（sprint），再分配给不同的工程敏捷（scrum）团队，"1Password 首席技术官 Nancy Wang 解释道。"而有了 Codex，你实际上可以 one-shot（一次性完成），从想法直接走到原型、再到能在生产环境完全跑通的功能。"

"对于我们的工作流来说，Codex 让 one-shot 功能变得更快、更轻松，只需给它一个用户故事和对期望用户体验的说明，就能大幅减少送交工程评审前所需的迭代轮次，"Wang 说。

这些工作已经催生了大量新功能，涵盖内部工具和面向客户的产品。一个例子是 Knox，一套完全代理化（agentic）的前端设计系统，帮助 1Password 的团队构建新界面。其他例子还包括一个内部人工智能（AI）站点可靠性工程（SRE）代理，以及一个 AI 支出管理工具。

1Password 让 Codex 在清晰划定的工程和安全边界内自主运行。"Codex 实际上会把所请求的功能拆解成功能规格，并搭建一个接近成型的原型，然后我们再交给系统工程师集成到后端，"Wang 说。这种方式缩短了交接时间，也提升了工程生产力。工程师写代码更快了，花在规划、实现、评审之间交接的时间也少了。

Codex 覆盖软件交付全生命周期

Codex 覆盖了从规划到上线的每一步：

- 规划与技术设计：将需求转化为规格说明、依赖检查和工作项。
- 跨技术栈实现：通过命令行界面（CLI）帮助工程师驾驭陌生的 Rust 和 TypeScript 代码；并行的工作树（worktree）让任务并发执行。
- 拉取请求评审：在人类评审员之前先审阅变更，标记逻辑问题和上下文缺失。
- 测试与发布就绪：与其他工作并行运行验收条件和自动化测试。
- 安全与访问：接入 1Password 内部的应用安全（AppSec）测试体系（harness）；通过密钥引用机制，确保明文凭证不会进入模型上下文。
- 生产环境排查：从事件管理、可观测性（telemetry）、源代码托管（source control）、告警寻呼（paging）、特性开关（feature flag）等渠道拉取证据。

成效一览

建模年度工程产能价值：783,750 美元，基于 50 名持续活跃的 Codex 开发者、单名开发者每年 25 万美元的完全人力成本、20.9% 的测得生产力提升、40% 的方向性 Codex 归因系数，以及 75% 的产能兑现率。

随着 Codex 集成到 1Password 的软件开发生命周期中，工程团队记录到了 20.9% 的生产力提升，以及拉取请求周期时间中位数下降 10.9%。一位工程师原本不在自己常用的技术栈上工作，借助 Codex 把通常需要三天的合并时间缩短到一天；一支团队面对固定的 Beta 发布日期，借助 Codex 完成了 4 个发布关键工单，而他们原本通常只能完成 2 个左右。

对于一个横跨 10 余个微服务的缺陷，排查时间从约两小时下降到 5–20 分钟。对于一个建模特化的 50 人 Codex 用户群组，1Password 估算年度工程产能价值约为 78.4 万美元，投资回报率（ROI）为 553%，相关产能被再投入到产品研发和内部创新中。若用户规模扩大到 100 名持续用户，假设 Codex 在测得生产力提升中占据更大份额，建模的年度产能价值可达约 310 万美元。

"如果我们真的能加速从客户反馈到快速修改 UI 之间的反馈循环，那将为业务带来巨大的释放效应。"，1Password 首席技术官 Nancy Wang

在开发提速的同时守住安全

1Password 也在把 OpenAI 的工具推广到财务、市场等团队，这些团队对聊天式界面已驾轻就熟。

对 1Password 而言，安全模型是采用 AI 工具时的设计前提，而不是使用规模扩大之后才加上的控制措施。"我们在产品构建方式上有着非常严格的安全姿态（posture），"Wang 说。例如，任何涉及凭证或密钥的产品，都必须遵循一套零知识（zero-knowledge）架构设计，确保只有客户自己能解密并访问其敏感数据。

1Password 通过在代码仓库中只存放密钥引用而非真实凭证来落实这一原则。当 Codex 调用一个经过审批的内部工具时，1Password 会在执行那一刻解析并注入凭证，这样明文值就永远不会进入模型上下文。

为了进一步加固安全，1Password 的工程师还把公司的安全策略"封装为可复用的应用安全技能（skills）"，让公司标准能随开发流程一起流转，Wang 解释道。"这是一个颠覆性的改变。"

未来展望

Wang 和 1Password 团队认为，在不久的将来，软件生产会通过"全民开发（democratized building）"变得更加触手可及：更多角色都可以构建软件。如果说第一波浪潮是工程师变成由 AI 辅助的构建者，那么 Wang 认为，"我们现在正稳稳地处在第二波浪潮中。产品、设计、研究、研发等所有岗位都在成为构建者。产品经理（PM）开始交付产品，设计师开始交付前端代码。"

Wang 预测这一趋势会扩散到每一个角色。"我认为最后一公里其实是让公司里的每一个人都能动手构建，"她说。"未来 12 个月我们会看到的是，那些传统上不写代码、或不认为自己会构建的人，会对 AI 工具熟悉到可以自信地交付代码。"
